## Defect 1: the owner decision R6 must obtain

Before R6.2 is built, the owner must decide whether `CurrentWork`'s updates can be Rust-owned while Python still owns runs and writes. The model wakes every 5 s and combines record tails with time, git, run observations, active executions and reconciliation (`P1.0` B1, C1-C3, E16; `current_work.py:501-675`). The acceptable outcomes are: (a) R6 defines one Rust work projection whose live inputs cross the reviewed snapshot seam and retires the Python thread/read model, or (b) the thread and every dependent route are named as remaining Python responsibility until R7 last. This document does not choose between them, and snapshotting the model is not a third option.

No new owner decision is required to begin the durable R4/R5 packages. The unresolved `CurrentWork` choice gates R6.2, not those packages. The other already-reserved owner decisions remain W0/write recovery and any deployment that restarts Python, changes Brain writes or interrupts runs.
