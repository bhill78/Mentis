## The search

The AST search walks every tracked `*.py` file in the checkout. Today those files are under `mentis/`, `tools/`, `tests/`, `crates/` and `docs/`; the one Python file under `docs/` has no caller, and there are currently no tracked Python files under `apps/`. It deliberately does not read untracked/generated files, dependencies, or non-Python files. The text searches below look for calls hidden in Python strings and by route or op name, plus the non-Python client/API references relevant to retirement.

```
# Aliased and function-local uses of the four modules, with the function each is in.
# A module used as a value is listed under <object>.
python tools/r5/retirement_callers.py

# What the AST can't follow: code in strings, and calls by route or op name.
git grep -n -E 'fluid\.objects|fluid\.search|conversation\.objectref|conversation\.render_check|import .*render_check|import .*objectref' -- '*.py'
git grep -n -E 'surface\.find\(|\bs\.find\(|\bm\.find\(|\"find\"' -- '*.py'
git grep -n -E 'read_model\(|_read_model\(' -- '*.py'
git grep -n 'check_rendering' -- '*.py'
git grep -n -E "/api/references|fluid/api/(search|document|object-refs)|'search\?|document\?|object-refs" -- apps tests tools crates
git grep -n -E '_fill_blocks|_fillable|_response_set_view|object_referenced_by_request|raise_from_reply' -- '*.py'
```

Callees come from walking each function's calls inside its module, or its class for `Surface`. The tables give test files, because a test goes when what it tests goes.

The AST output lists each use of a name bound by an import of one of the four modules: an attribute of the module, an imported name, or the module itself as a value. **So before deleting an attribute, read the `<object>` lines of its module as well as its own group.** This is what the script and searches show, and these are the limits on it:

- The script doesn't follow a value further: `x = objects` is listed at that line, and a later `x.answers` is not. A value passed to another function is the same.
- It follows names bound by `import` and `from` statements, not `import mentis.fluid.objects` with the dotted name, a parent package (`fluid.objects.check`), `import *`, or a dynamic import. A local that shadows an imported name is listed as a use of the module.
- It knows nothing of `Surface`. The `Surface.find` callers come from the second text search, which matches only the receivers `surface`, `s` and `m`, and the op name in double quotes. A call through another name or a bound method isn't matched.
- A text search matches literal text. A route or op name built at run time isn't matched, and a match is not always a caller, so its lines have to be read.

A separate probe at this commit, on both trees, found no dotted import, parent-package use, `import *`, rebinding of a module, or dynamic import of these modules, and binding each scope's imports before walking it changed no count. That probe isn't part of the search, so it says nothing about a later tree.

## Forward cases no package owns

Python can't retire these routes until Rust answers these cases, and no package in `R4-R8-reconcile.md` is given them. At the latest, R8 has to settle them, because Python is gone then and a forward has nowhere to go.

- `/fluid/api/search`: non-ASCII search text.
- `/fluid/api/document`: unreadable files, and locators with no valid digest.
- `/fluid/api/object-refs`: more than 64 references, extraction engine failures, non-text fields.
- `find` and `/api/references?q=`: a matching Turn with a fill block.
