Manage Sources in Quiet Chat

Design round 1 · mockups with sample data · nothing here is implemented. Each page is full-size, in Quiet Chat’s own layout and stylesheets; open it in a normal window.

The views

    What these show, and what they leave out

    ShownWhere it comes from in the existing source system
    Kinds: Folder, Git repository, SQLite databaseThe three working connectors. Slack, Jira, Confluence, Gmail, HTTP API, Web, RSS/Atom are listed as not available yet, as the system itself describes them.
    Connected here / Not connected on this machine / Declared, nothing taken yetThe three states a source reports, in plainer words.
    Refreshing now, with files and bytes so far, and CancelA running refresh reports files, bytes and the current file. No percentage or time remaining exists.
    Last refresh failed, with Git’s reasonThe four Git failure kinds. Kept only until Mentis restarts.
    Refresh (preview first), Change what is included, Stop refreshing here, Locate itThe preview, refresh, scope-revision, unbind and bind operations.
    Counts, refresh history, withheld files, what is includedWhat each source already reports.

    Left out because the source system does not have them: rename, remove, turn off, a separate connection test, scheduled refresh, entering or storing passwords, and limiting which agents can read a source. Those are owner decisions, listed in the report.
